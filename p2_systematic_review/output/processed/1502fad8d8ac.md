## Abstract summary
This work presents an augmented reality (AR) application integrated with an IoT sensing device (S‑NODE) and an MS SQL backend to support predictive maintenance workflows. Sensor data from S‑NODE devices are stored in the cloud and, via a Unity/Vuforia AR app using QR-coded device IDs, live device parameters and predictive health indicators are visualized for hands‑free inspection and maintenance decision support. This chapter applies quantum-inspired methods—specifically Hamiltonian Monte Carlo (HMC) simulation—to estimate survival functions and assess investment risk for renewable-energy stocks. Using daily 2020–2023 data for eight major renewable-energy companies, the authors identify recommended holding horizons (roughly 5–12 months) and highlight stocks (notably CSIQ and CWEN) with favorable survival probabilities, while noting HMC's strengths for continuous distributions and its limitations with mixed discrete/continuous time series.
## Methodology
This conference work implements an end-to-end augmented-reality (AR) application that visualizes live machine-sensor telemetry collected by an IoT sensing node (S-NODE). The methodological pipeline comprises: (1) sensing: S-NODE devices equipped with various low-power sensors (temperature, vibration, proximity, air-quality, etc.) collect machine data and transmit these readings via an RF link to a modular gateway; (2) gateway/cloud ingestion: the gateway forwards data to a cloud endpoint using MQTT and data is persisted into an MS SQL database keyed by a device UID; (3) AR client: an Android application built in Unity with the Vuforia AR SDK is developed to detect a model target (S-NODE physical model) and scan an associated QR code (containing the device UID); (4) data lookup & rendering: the Unity app queries the MS SQL backend (via an API) using the UID, retrieves the device type and associated sensor values, and renders contextual AR overlays (numerical parameters, trends) anchored to the tracked S-NODE model; (5) optional model-target generation: Vuforia Model Target Generator is used to prepare 3D models for stable object tracking. No machine-learning model training for prediction is described in the paper; the focus is on system integration, real-time data retrieval, and AR visualization of device telemetry to support maintenance tasks. The study trains and compares two supervised machine-learning approaches—a Deep Neural Network (DNN) and a Random Forest (RF) regressor—to approximate the diamond-film growth-rate response surface as a function of three process parameters (substrate temperature, gas pressure, methane concentration). The authors use a small experimental dataset (20 samples) taken from a prior Design-of-Experiments study (Jiang et al., Table 2) as the training set. They preprocess features for the DNN with feature normalization (min–max or standardization discussion; DNN trained on normalized features), while RF is used without scaling (scale-invariant). The RF is used both as a predictive model and to estimate feature importance via Mean Decrease in Impurity (MDI) and permutation importance. The DNN architecture was optimized via hyperparameter tuning; the chosen architecture had six hidden layers with ReLU activations, was trained with the Adam optimizer and MSE loss, and evaluated with tenfold cross-validation (leaving out 2 samples per fold given the 20-sample set). Performance is reported primarily as mean absolute error (MAE) on training and held-out test folds and compared against prior polynomial regression / response-surface baselines (linear, interaction, quadratic). Residual analyses and feature-importance comparisons are also presented to interpret model behavior and parameter influence.

**Algorithms used:** Deep Neural Network (feedforward with ReLU activations), Random Forest regressor
**Frameworks:** Unity, Vuforia (Model Target Generator & SDK), MQTT, MS SQL, Android SDK

**Experimental setup:** S-NODE devices with embedded sensors transmit via RF to a modular gateway which publishes telemetry to cloud via MQTT. Telemetry is persisted in an MS SQL database. An Android application (Unity + Vuforia) running on commodity Android phones/tablets is used as the AR client. The app performs model-target tracking and QR-code scanning to obtain device UID, queries the MS SQL backend for latest sensor values (per device type), and renders AR overlays in real time.

**Dataset:** Live sensor telemetry streams produced by S-NODE devices mounted on industrial machinery (device UID, device type, timestamped sensor measurements such as temperature, vibration, proximity, air quality, etc.). Data are stored in an MS SQL backend. No public/standard dataset is used or reported.
