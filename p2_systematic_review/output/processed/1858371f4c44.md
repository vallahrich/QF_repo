## Abstract summary
This preprint presents an agentic framework that automates end-to-end portfolio optimization with a LangGraph-orchestrated DAG of eight specialized agents handling policy, data ingestion, QAOA circuit construction from live Yahoo Finance data, simulation pre-validation, cloud submission via the QBraid runtime, quality gating, and artifact generation. The QAOA ansatz maps annualized returns and pairwise covariances to single- and two-qubit rotations; experiments on two QBraid-backed cloud simulators show consistent measurement distributions and a dominant, high-Sharpe portfolio, while a maturity-gated governance model controls hardware access and the agentic overhead remains under 2% of pipeline time.
## Methodology
The study implements an end-to-end, agent-orchestrated pipeline that takes live financial market data and produces QAOA-based portfolio-selection samples on cloud quantum simulators. The workflow is decomposed into eight single-responsibility agents coordinated by a LangGraph DAG state machine: PolicyAgent (maturity-gated resource permissions), Planner (task decomposition and routing), AutoCircuitDesigner (constructs a QAOA ansatz from market data), SimulationSandbox (local pre-validation via Qiskit simulators or fallback random generator), QPUBroker (backend selection and submission through the QBraid runtime), Result Polling (asynchronous job monitoring), QCAAgent (statistical quality gate), Aggregator (provenance-tracked artifact generation) and RejectionHandler. Market data (one year of daily closes) are fetched from Yahoo Finance using yfinance; daily log-returns are computed and annualized to produce per-asset expected returns and an annualized covariance matrix. These empirical parameters directly determine QAOA gate angles: single-qubit RZ angles encode returns (γ_i^(l) = l * μ_i * π), two-qubit ZZ interactions are implemented as CX–RZ(γ_ij)–CX with γ_ij^(l) = l * C_ij * π/2, and mixer RX rotations use β_i^(l) = l * 0.4 * π / p. The circuit uses n qubits (assets) with p alternating cost/mixer layers, is prepared from H⊗n, executed locally for pre-validation (Qiskit BasicSimulator / Aer) and then submitted via QBraid to cloud simulator backends. Measurement counts are retrieved, checked against a simple statistical gate (normalized mean > 0), and translated into equal-weight portfolios for financial evaluation (annualized return, portfolio volatility, Sharpe ratio). The presented experiments used n=5, p=5, produced a compiled circuit (≈210 gates, depth 93), and were executed on two QBraid-accessible simulators to assess cross-platform consistency and end-to-end orchestration performance.

**Algorithms used:** QAOA
**Frameworks:** Qiskit, Qiskit Aer, LangGraph (StateGraph), QBraid SDK / runtime, yfinance

**Experimental setup:** 5-qubit QAOA circuit with p=5 layers (H⊗5 initial state, data-driven RZ and ZZ cost unitaries, RX mixers). Local pre-validation on Qiskit BasicSimulator (1000 shots). Cloud execution via QBraid: AWS Tensor Network simulator (aws:aws:sim:tn1, 1000 shots) and QBraid QIR state-vector simulator (qbraid:qbraid:sim:qir-sv, 2000 shots). Compiled circuit: ~210 gates, transpiled depth 93.

**Dataset:** One year of daily closing prices (≈252 trading days, ending February 2026) for five tickers fetched from Yahoo Finance via the yfinance library: AAPL, XOM, JPM, JNJ, GLD. Preprocessing: compute daily log-returns r_t = log(p_t / p_{t-1}), annualize returns and covariance using 252 trading days.

## Findings
- [supported] An agentic DAG-based workflow (implemented with LangGraph) can orchestrate an end-to-end quantum portfolio optimization pipeline composed of eight specialized agents (policy, planner, auto-circuit, simulation sandbox, QPU broker, polling, quality control, aggregator/rejection handler).
- [supported] The system constructs a data-driven QAOA circuit where single-qubit RZ angles are derived from annualized returns and two-qubit ZZ interaction angles are derived from empirical covariance entries (live Yahoo Finance data for 5 assets).
- [supported] The full pipeline (circuit construction → local pre-validation → cloud submission → polling → quality gate → artifact generation) was executed on QBraid-backed cloud simulators (AWS tensor-network sim and QBraid QIR state-vector sim).
- [supported] Cross-platform measurement consistency was observed: normalized measurement distribution means agreed to within 0.0001 across local simulator and two cloud simulator backends.
- [supported] The dominant measured bitstring (01011 → portfolio AAPL+XOM+JNJ) appeared at 23.55% frequency (7.6× uniform baseline) and corresponds to an evaluated annualized return 31.17%, volatility 19.29%, Sharpe 1.62 (equal-weight allocation).
- [supported] The top-5 measured bitstrings accounted for 67.60% of shots, indicating a strongly non-uniform output distribution induced by the cost Hamiltonian.
- [supported] The agentic orchestration overhead is negligible: state routing and orchestration consumed ~0.108 s (≈0.4% of total 27 s wall-clock for AWS TN1 run), i.e., under the claimed 2% overhead.
- [supported] The SimulationSandbox pre-validation detected a non-trivial distribution (all 32 bitstrings observed) and yielded a normalized mean consistent with cloud runs, enabling safe cloud submission.
- [speculative] The maturity-gated governance model (mapping job maturity levels to backend/shot permissions) can prevent inadvertent expenditure on paid QPUs during development (model described and enforced by policy agent but not tested on paid hardware).
- [speculative] The paper claims novelty in being the first application of agentic AI orchestration to quantum optimization workflows (presented as a positioning claim rather than an exhaustively validated bibliographic fact).
- [supported] QBraid’s runtime abstraction enabled submission of the same Qiskit circuit object to heterogeneous backends without code modification in these experiments (simulator backends).
- [supported] The covariance-encoded ZZ interactions produced interpretable selection/exclusion behavior (e.g., GLD excluded from the dominant portfolio due to higher covariance penalties).
- [supported] The paper documents implementation-level resource characteristics (gate counts, compiled depth, OpenQASM instruction counts) for the n=5, p=5 circuit.
- [supported] Limitations are clearly acknowledged: small problem scale (n=5), simulator-only cloud execution (no physical QPU runs), non-variational parameter choice, single-run evaluation, and equal-weight post-processing assumption.

**Results summary:** The authors implemented and ran an end-to-end agentic orchestration framework that automates data retrieval, data-driven QAOA circuit construction, local pre-validation, cloud simulator submission via the QBraid runtime, asynchronous polling, statistical quality gating, and provenance-tracked artifact generation. Using one year of Yahoo Finance data for five assets (AAPL, XOM, JPM, JNJ, GLD) the system produced a strongly non-uniform measurement distribution on simulators: the dominant bitstring (AAPL+XOM+JNJ) appeared with 23.55% frequency and yielded a Sharpe of 1.62. Cross-platform simulator runs showed measurement means agreeing within 0.0001, and the orchestration overhead was negligible (~0.4% of total wall-clock time). The paper emphasizes architecture, governance, and reproducibility rather than any claim of quantum computational advantage.

## Quantum advantage claim
**Classification:** not-applicable

No claim of quantum advantage is demonstrated. Experiments were run on simulators for a classically trivial n=5 instance; results demonstrate orchestration, data-driven parameterization, and cross-platform reproducibility rather than superiority over classical methods. The paper explicitly notes limitations (small scale, simulator-only, non-variational parameters) and frames contributions as operational/architectural, not as evidence of quantum computational advantage.
## Limitations
- Problem scale: demonstration limited to n = 5 assets (5 qubits), a classically trivial instance; value for larger, practically relevant n is unproven.
- Non-variational QAOA parameters: rotation angles are analytically/data-driven rather than obtained via a variational outer-loop, which may limit solution quality.
- Simulator-only cloud execution: experiments ran on simulators (QBraid/AWS simulators); no execution on physical QPU hardware was performed.
- Single-run evaluation: results are from individual pipeline executions without repeated runs or bootstrapped confidence intervals for financial metrics.
- Equal-weight allocation for financial evaluation: within-subset weight optimization was not performed (selected portfolios evaluated with equal weights).
- Real hardware noise and error mitigation untested: the framework did not evaluate noise effects or incorporate error mitigation strategies despite their expected importance on real QPUs.
- [inferred] Pre-validation and quality gating are simplistic (e.g., QCA threshold mean > 0) and may fail to detect subtle or systematic problems in outputs.
- [inferred] Scalability of the agentic orchestration (state size, number of agents, parallel QPU submissions) is untested; agentic overhead may rise with problem scale and concurrency.
- [inferred] Dependence on QBraid and Qiskit abstractions: portability and semantic preservation across other runtimes, direct vendor APIs, or non-Qiskit circuit representations are not fully validated.
- [inferred] Empirical hyperparameter choices (mixer coefficient 0.4, linear layer scaling of cost angles) were selected heuristically and may not generalize across datasets, assets, or circuit depths.
- [inferred] Governance and cost estimates are approximate and static; real-world pricing dynamics, quotas, and organizational policy complexity may complicate the maturity-gated model.
- [inferred] Circuit depth, gate counts and resulting compilation/transpilation requirements may be prohibitive on current noisy hardware as n grows, limiting practical applicability without additional circuit reduction or error mitigation techniques.
- [inferred] The impact of transpiler optimizations and hardware-specific constraints on final measurement distributions (beyond the tested simulators) is not characterized.
## Open questions
- How will the framework and the data-driven QAOA parameterization perform on physical, noisy QPUs (including the effect of decoherence, gate errors and readout noise)?
- How does solution quality, measurement distribution concentration, and orchestration overhead scale with problem size (e.g., n >= 20, n >= 50)?
- Would incorporating a variational outer loop to optimize QAOA parameters materially improve outcomes relative to the analytic/data-driven angles, and what is the added computational and orchestration cost?
- How well does the Planner’s decomposition approach (e.g., correlation-based partitioning) integrate with the agent pipeline for large asset universes and parallel QPU jobs?
- What are effective, noise-aware statistical quality gates and divergence measures that reliably separate useful quantum signal from hardware/systematic noise?
- Can multi-objective Hamiltonians (e.g., encoding Sharpe ratio or other risk-adjusted objectives) be formulated and executed efficiently within this agentic workflow?
- How robust are measurement distributions to different transpilation strategies and backend-specific optimizations, and are there subtle cross-platform biases in practice on hardware?
- How should maturity-gated governance thresholds, shot budgets, and backend permissions be calibrated in production environments to balance exploration, cost, and risk?
- What level of repetition and statistical sampling is required to produce stable, actionable financial recommendations from quantum-sampled portfolios?
- How does live-data variability (market non-stationarity) affect reproducibility and the interpretability of artifacts across time, and what snapshot/versioning best practices are required?
- Can the agentic orchestration handle dynamic, real-time backend selection under changing availability, queue times, and calibration data at production scale?
- What security, auditability and compliance implications arise when integrating cloud quantum runtimes into regulated financial workflows?

**Future work:**

- Implement correlation-based decomposition in the Planner for large asset universes, enabling partitioning and parallel QPU submissions.
- Enable dynamic backend selection based on real-time availability, queue depth, and calibration data (runtime-aware device routing).
- Develop noise-aware quality gating using statistical divergence measures and more sophisticated QCA criteria.
- Design and evaluate multi-objective cost Hamiltonians that directly encode objectives such as the Sharpe ratio.
- Parallelize QPUBroker instances to support concurrent subproblem execution and scale-out orchestration.
- Integrate error mitigation techniques and noise-aware transpilation strategies for execution on real QPUs.
- Extend the financial evaluation to include within-subset weight optimization (optimal weights for selected assets) rather than equal-weight allocations.
- Perform repeated runs and bootstrap statistical analysis to produce confidence intervals on financial metrics and distributional stability.
