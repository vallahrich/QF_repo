## Abstract summary
This preprint introduces CVQBoost, a boosting algorithm formulated as a continuous quadratic optimization designed to run on Quantum Computing Inc.'s Dirac-3 entropy quantum computing (EQC) hardware. Applied to credit card fraud detection and large synthetic datasets, CVQBoost attains comparable AUC to XGBoost while substantially reducing training time and demonstrating superior scaling compared to multicore and GPU XGBoost implementations.
## Methodology
The study introduces CVQBoost, a boosting algorithm that formulates the weak-classifier weighting problem as a continuous quadratic optimization and leverages Quantum Computing Inc.'s Dirac-3 Entropy Quantum Computing (EQC) photonic-hybrid device as a continuous quadratic solver. Weak classifiers (implemented primarily as logistic regression models built from one- or two-feature subsets) are combined linearly with non-negative continuous weights wi subject to a normalization constraint (sum_i wi = 1). The training objective minimized is a squared-error loss across labeled training samples plus an L2 regularization term: min_w sum_s (sum_i wi hi(xs) - ys)^2 + lambda * sum_i (wi)^2. The quadratic form is expressed via Jij = sum_s hi(xs) hj(xs) + delta_ij * lambda and Ci = -2 sum_s ys hi(xs) and is solved by Dirac-3; additional solver comparisons used Hexaly (commercial optimizer) and SciPy SLSQP. Experiments benchmark CVQBoost against XGBoost across multiple hardware configurations (single-core, multi-core up to 48 cores, GPUs up to four NVIDIA L4) and datasets (the Kaggle Credit Card Fraud Detection dataset and large synthetic datasets generated with scikit-learn's make_classification). Imbalanced-class handling strategies (ADASYN, SMOTE, SMOTE-SVM, and majority downsampling) were applied to training data while the test set remained unchanged. Performance metrics included AUC for classification quality, runtimes (seconds) and solution energy (objective value) for solver comparisons. Results report averages over repeated runs (typically 5–10) with error bars given as two standard deviations.

**Algorithms used:** CVQBoost (continuous-variable boosting using Dirac-3 EQC), QBoost (referenced / conceptual predecessor), XGBoost (baseline), Logistic Regression (used as weak classifiers), Sequential Least Squares Programming (SLSQP) via SciPy, Hexaly optimizer (commercial solver), ADASYN (oversampling), SMOTE, SMOTE-SVM, Majority class downsampling, make_classification (scikit-learn synthetic data generator)
**Frameworks:** XGBoost library, NVIDIA RAPIDS AI (used for GPU XGBoost), scikit-learn, SciPy

**Experimental setup:** Dirac-3 (QCi) used as the native continuous quadratic solver; comparisons run on conventional hardware including single-core CPU, multi-core machines (experiments on 8-core, 16-core, and a high-performance machine with up to 48 CPU cores at 2.64 GHz), and GPU acceleration with up to four NVIDIA L4 GPUs (24 GB each) via NVIDIA RAPIDS AI. Kaggle Credit Card Fraud dataset (~200k transactions, 38 features) used for classification accuracy and moderate-scale runtime tests. Large-scale synthetic datasets created with scikit-learn (1M–70M samples, 100–900 features) were used for scalability benchmarks. Runtimes reported in seconds; experiments repeated (typically 5–10 runs) and averaged; error bars are two standard deviations.

**Dataset:** Kaggle Credit Card Fraud Detection dataset (MACHINE LEARNING GROUP – ULB, 2013): ~200,000 transactions, 38 features, highly imbalanced (~0.1% fraudulent). Additionally, synthetic datasets generated with scikit-learn's make_classification ranging from 1 million to 70 million samples with 100 to 900 features (80% used for training).

## Findings
- [supported] CVQBoost (the continuous-variable boosting algorithm) obtains comparable classification accuracy (AUC) to XGBoost on the Kaggle Credit Card Fraud dataset when common class-balancing techniques (ADASYN, SMOTE, SMOTE-SVM, downsampling) are applied.
- [supported] In some balanced-training settings (example: ADASYN with minority:majority ratio = 1.0) CVQBoost slightly outperforms XGBoost on AUC (paper example: CVQBoost AUC 0.8855 vs XGBoost AUC 0.8826).
- [supported] CVQBoost running on QCi’s Dirac-3 hardware shows substantially shorter training runtimes than single-core XGBoost as dataset size and number of features increase (paper example: for 150k training samples CVQBoost total time ~2.2s vs XGBoost on 1 core ~117.4s).
- [supported] CVQBoost on Dirac-3 exhibits favorable scaling with training data size and feature dimensionality (near-linear scaling reported), whereas XGBoost shows much faster runtime growth and diminishing returns when parallelized across many CPU cores or GPUs.
- [supported] On very large synthetic datasets (1M–70M samples, up to 900 features) the authors report that CVQBoost on Dirac-3 scales better (runtime advantage) than XGBoost run on 48 CPU cores or four NVIDIA L4 GPUs.
- [supported] When the same CVQBoost Hamiltonians are solved with other solvers, Dirac-3 demonstrates superior runtime scaling for large problem sizes relative to Hexaly and SciPy SLSQP, though solution energies can be slightly worse for problems with large dynamic range.
- [supported] The authors observed a practical limitation: Dirac-3 performance is affected when the Hamiltonian dynamic range exceeds ~23 dB, which can impact solution quality on high-dynamic-range problems.
- [speculative] The paper asserts (but does not empirically measure) that using Dirac-3/CVQBoost yields power-efficiency advantages compared to classical GPU/CPU training.
- [speculative] The authors propose that CVQBoost’s structure offers enhanced explainability (by inspection of highly weighted weak classifiers) making it attractive for regulated domains like finance and scientific applications; this is discussed but not demonstrated in-depth in the experiments.
- [speculative] The claim that CVQBoost is broadly a promising alternative to gradient boosting methods for many high-dimensional ML applications is presented as an outlook/generalization beyond the datasets and hardware tested.

**Results summary:** The preprint introduces CVQBoost, a continuous-variable boosting algorithm designed to run on Quantum Computing Inc.'s Dirac-3 entropy quantum computing hardware. On the Kaggle credit-card fraud dataset (and on large synthetic datasets up to 70M samples), CVQBoost achieved AUC scores comparable to XGBoost when class-balancing techniques were applied, and in some balanced settings it slightly exceeded XGBoost. Importantly, CVQBoost on Dirac-3 demonstrated a substantial runtime advantage and more favorable scaling behavior versus XGBoost run on single-core, multi-core (up to 48 cores) and multi-GPU (up to 4 × NVIDIA L4) classical hardware. Solver comparisons also showed Dirac-3 scaling better than Hexaly and SciPy SLSQP for large Hamiltonians, though solution energies degraded slightly for very large dynamic ranges that exceed Dirac-3's operational limit (~23 dB). The authors note potential explainability benefits and suggest power-efficiency advantages, but power was not measured in the presented experiments.

## Limitations
- Dirac-3 has a known performance limitation at 23 dB dynamic range which can impact optimization quality for Hamiltonians with larger dynamic ranges (author-stated).
- CVQBoost attains comparable accuracy to XGBoost primarily after class-balancing techniques are applied; for heavily imbalanced training sets (minimal balancing) XGBoost outperforms CVQBoost (author-stated).
- For small datasets XGBoost is faster; CVQBoost's runtime advantage appears only beyond a certain dataset size threshold (author-stated).
- Solutions found by Dirac-3 exhibit a slight energy gap relative to other solvers on larger problem instances (author-stated).
- CVQBoost runtimes show high variability across runs (author-stated).
- All authors and the work are fully supported by Quantum Computing Inc., presenting a potential conflict of interest (author-stated disclosure).

## Open questions
- How well does CVQBoost generalize to other real-world financial datasets (different fraud types, geographies, feature distributions) and to other application domains beyond fraud detection?
- How does CVQBoost perform with a wider variety of weak classifiers (decision trees, Gaussian processes, Naive Bayes, etc.) and with ensembles of heterogeneous weak learners?
- Can the positivity and sum-to-one constraints on weights be relaxed or otherwise adapted to improve model expressivity without sacrificing Dirac-3 compatibility?
- What are the precise causes of the observed runtime variability of CVQBoost runs on Dirac-3, and how can variability be reduced?
- How do hardware imperfections, noise, and dynamic-range limitations of Dirac-3 affect solution quality and reproducibility in real-world deployments?
- Can the dynamic-range limitation (23 dB) be mitigated by preconditioning, rescaling, regularization, or hardware improvements, and what are practical strategies to do so?
- What are the formal optimization guarantees (if any) for CVQBoost when solved on Dirac-3 relative to classical solvers — e.g., bounds on suboptimality or probabilistic guarantees?
- How does CVQBoost compare to other modern gradient boosting implementations such as LightGBM or CatBoost in accuracy and runtime across a range of datasets and hardware configurations?
- What are the end-to-end costs and benefits (including pre/post-processing, data movement, queuing/latency to access Dirac-3) for production deployment compared to optimized classical pipelines?
- What are the measured power and energy consumption characteristics of CVQBoost on Dirac-3 versus GPU/CPU baselines under comparable workloads?
- How interpretable and actionable are the explanations purportedly available from highly weighted weak classifiers in real regulatory or operational contexts (e.g., GDPR compliance, auditability)?
- How does CVQBoost scale in distributed or multi-device settings, and what bottlenecks (networking, orchestration) arise at production scale?
- What is the impact of extremely high dimensionality (beyond tested ranges) and feature engineering choices on both accuracy and runtime of CVQBoost?
- How sensitive are results to hyperparameters (e.g., regularization λ, number/selection of weak classifiers), and what automated tuning strategies are effective?

**Future work:**

## Key ideas
- #idea:quantum-advantage — CVQBoost on Dirac-3 achieved comparable AUC to XGBoost while reporting substantially reduced training time and better scaling behavior than single-/multi-core and multi-GPU XGBoost on the tested datasets.
- #idea:hybrid-approach — The pipeline is hybrid: classical weak learners (logistic regressions on 1–2 feature subsets) are combined via continuous non-negative weights; the continuous quadratic program (J, C) built from training data is solved on the Dirac-3 EQC device with classical pre- and post-processing.
- #idea:near-term-feasibility — The authors ran end-to-end experiments on real Dirac-3 hardware and benchmarked against optimized classical hardware (up to 48 CPU cores and up to four NVIDIA L4 GPUs), and evaluated scaling on synthetic datasets up to 70M samples.
- #limitation:noise — The Dirac-3 device has an operational dynamic-range limitation (~23 dB) noted by the authors, which constrains solver precision and may affect solution quality.
- #limitation:data-encoding — The approach requires building Jij and Ci (sums over training samples) for the quadratic solver (a form of Hamiltonian construction), which can be costly for very large datasets and may shift runtime burden to preprocessing.
- #limitation:no-empirical-validation — Although real hardware was used, some solver hyperparameters (e.g., regularization lambda) are not fixed/clearly reported, and solver tolerance/termination settings differ across solvers, reducing reproducibility and making head-to-head claims harder to validate.
## Contradictions
- #contradiction:classical-vs-quantum — The paper claims substantial training-time advantages over XGBoost (including GPUs), but it's unclear whether the comparisons fully account for end-to-end preprocessing/postprocessing costs, solver parameter tuning, and equivalent engineering optimizations of the classical baselines (e.g., RAPIDS/XGBoost hyperparameter and system tuning). This raises doubt about the extent of the claimed quantum superiority.
- #contradiction:scalability — Superior scaling is reported on very large synthetic datasets, yet the Dirac-3 device has a finite dynamic range (~23 dB) and the manuscript omits fixed values for regularization and some solver settings; together, these factors leave open whether the observed scaling will hold on noisy real-world data and across different problem formulations.
