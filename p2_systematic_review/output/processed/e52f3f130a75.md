## Abstract summary
The paper proposes SparseEA-AGDS, a hybrid graph-based evolutionary optimization framework that partitions workloads across hybrid quantum–classical systems using attributed task graphs, dominance-guided adaptive genetic operators, and a dynamic security scoring mechanism. Simulation results show the method improves execution efficiency and reduces inter-platform communication while enforcing security constraints, reporting up to ~21.8% reduction in makespan, improved security compliance, and near-linear scalability with minimal degradation as workload size increases.
## Methodology
The study models hybrid quantum–classical workloads as directed attributed task graphs (DAGs) where each task node has quantum and classical cost estimates and a security-sensitivity score. A dominance-based multi-objective evolutionary algorithm (SparseEA-AGDS) searches the space of binary assignment vectors (task->quantum or classical) to jointly optimize makespan, security risk, and resource balance. SparseEA-AGDS extends standard EAs with dominance-layer ranking, adaptive genetic operator rates (mutation and crossover adjusted by dominance), graph-aware crossover that preserves strongly connected subgraphs, and a sparsity-aware, security-constrained mutation operator that suppresses mutations for high-sensitivity tasks. A dynamic scoring function combines execution time, security risk (penalty phi for unsafe assignments), and resource imbalance with adaptive weights (alpha, beta, gamma) updated by dominance information. Security feasibility is enforced by a constraint R(x) <= R_max; infeasible solutions are penalized or discarded. The algorithm was implemented in Python (NetworkX, NumPy) and evaluated in a classical simulated hybrid environment using synthetically generated DAG workloads of varying sizes. Performance was assessed against three baselines (simple genetic algorithm, a generic multi-objective EA, and a fixed hybrid evolutionary model) using metrics including makespan, normalized inter-platform communication cost, convergence iterations, security-compliance ratio, and scaling efficiency. Results were averaged over multiple independent runs.

**Algorithms used:** SparseEA-AGDS (dominance-layer adaptive EA with graph-aware crossover and security-aware sparse mutation), Simple Genetic Algorithm (SGA), Multi-Objective Evolutionary Algorithm (MOEA), Fixed Hybrid Evolutionary Model (SHEM)
**Frameworks:** Python, NumPy, NetworkX

**Experimental setup:** Implemented in Python on a classical computing environment that simulates hybrid quantum-classical execution. Quantum execution costs and latencies were abstracted via calibrated latency models; no real QPU was used. The simulator models inter-platform communication costs and multicore classical scheduling assumptions.
## Experiment details
### Input
Synthetic directed acyclic graphs (DAGs) generated to represent hybrid workloads. Task counts evaluated included small-scale (100 tasks) and large-scale (up to 1000 tasks; intermediate 500 tasks reported). For each task: quantum and classical execution costs sampled from bounded distributions; a security sensitivity score s_i in [0,1] assigned. Dependency density was limited to reflect realistic data-flow. Source: synthetically generated by the authors (no external dataset). No special preprocessing beyond graph construction and random initialization of partitions was reported.

### Process
Pipeline: 1) Generate synthetic DAG (nodes annotated with c_i^q, c_i^c, s_i). 2) Initialize population of P candidate partition vectors (binary assignments) randomly. 3) Evaluate each individual: compute T(x) (execution cost including cross-platform transfer costs), R(x) (security risk = sum s_i * phi(x_i)), and composite fitness F(x) = alpha*T(x) + beta*R(x) + gamma*C(x). 4) Perform nondominated sorting (dominance layers) to rank population. 5) Adapt mutation and crossover rates per individual based on dominance layer (higher-ranked individuals receive lower mutation on security-critical variables). 6) Apply graph-aware crossover that preserves strongly linked subgraphs. 7) Apply security-aware sparse mutation (suppress mutation for tasks with s_i above threshold). 8) Enforce feasibility: discard or penalize solutions with R(x) > R_max. 9) Select next generation based on dominance and feasibility. 10) Repeat for Gmax generations. Parameters reported: population size P=100, max generations Gmax=100, initial mutation rate 0.1, initial crossover rate 0.8; rates adapt during evolution. Results averaged over multiple independent runs to reduce stochastic variance.

### Output
Outputs: best non-dominated partitions (binary assignment vectors) and aggregated metrics per experiment. Quantitative metrics reported: makespan (ms), normalized inter-platform communication cost, number of convergence iterations, security-compliance ratio (fraction of candidate solutions meeting R(x) <= threshold), and scaling efficiency (T(n) / (n log n)). Baselines compared: SGA, MOEA, SHEM. Example reported table values: Makespan: SGA 1420 ms, MOEA 1285 ms, SHEM 1210 ms, SparseEA-AGDS 1085 ms; Communication cost: SGA 0.38, MOEA 0.31, SHEM 0.29, SparseEA-AGDS 0.21; Convergence iterations: SGA 210, MOEA 185, SHEM 172, SparseEA-AGDS 136. Security compliance and scaling efficiency across sizes 100/500/1000: compliance ~98.6%/97.9%/97.2%; runtimes 1.8s/6.4s/13.1s; scaling efficiency 0.92/0.89/0.87. Relative improvements (percentages) versus baselines are reported (e.g., up to 21.8% makespan reduction).

## Findings
- [supported] The SparseEA-AGDS algorithm (a dominance-layer guided, sparsity-aware EA with graph-aware crossover and security-aware sparse mutation) was implemented and evaluated in simulation.
- [supported] In synthetic DAG simulation experiments, SparseEA-AGDS produced a lower makespan (1085 ms) than baseline algorithms (SGA: 1420 ms, MOEA: 1285 ms, SHEM: 1210 ms).
- [supported] SparseEA-AGDS achieved lower normalized inter-platform communication cost (0.21) compared to baselines (0.29–0.38) in the simulated workloads.
- [supported] SparseEA-AGDS converged faster in the experiments (136 iterations) compared to baselines (MOEA 185, SHEM 172, SGA 210), indicating improved convergence behavior in the simulations.
- [supported] The method maintained high security compliance in simulation runs: compliance ≈ 98.6% (n=100), 97.9% (n=500), 97.2% (n=1000).
- [supported] Scalability in simulation: runtime growth was reported to be near-linear with problem size, with a normalized scaling-efficiency metric declining from 0.92 (n=100) to 0.87 (n=1000), corresponding to <6% degradation as size increased.
- [supported] The algorithm enforces a security feasibility constraint (R(x) ≤ R_max) and suppresses mutation on tasks above a sensitivity threshold; these mechanisms were implemented in the experimental framework.
- [speculative] Claims that SparseEA-AGDS will transfer directly to real hybrid quantum–classical hardware (including noisy QPUs, decoherence effects, and real quantum execution costs) are theoretical and were not empirically validated on physical QPUs.
- [speculative] Statements about direct applicability and benefits to high-security real-world domains (cryptography, healthcare analytics, financial optimization) are suggested but not demonstrated empirically in those domains.
- [disputed] The paper contains inconsistent phrasing about security metrics (it reports very high security compliance rates in tables but elsewhere claims a '25.6 % lower security compliance metrics' or a 25.6% improvement).
