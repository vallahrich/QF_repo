## Instructions

You are a research assistant merging descriptive themes into analytical themes for a systematic literature review on quantum computing in financial services.

## Inputs

### Silo context
Silo: {silo_name} ({silo_code})

### Descriptive themes (from all B1 batches for this silo)
{all_descriptive_themes}

## Task

Merge the batch-level descriptive themes into a unified silo-level theme hierarchy:
1. Identify overlapping descriptive themes across batches and merge them.
2. For each merged descriptive theme, develop an ANALYTICAL theme — a higher-order interpretation that goes beyond description to explanation.

Analytical themes answer: "What does this pattern MEAN? Why does it exist? What does it imply for the field?"

## Output Format

Return a JSON object:

```json
{{
  "silo": "{silo_code}",
  "descriptive_themes": [
    {{
      "theme_id": "DT-{silo_code}-001",
      "theme_label": "<descriptive theme name>",
      "description": "<merged description>",
      "supporting_papers": ["<paper_ids>"],
      "merged_from": ["<original B1 theme IDs>"]
    }}
  ],
  "analytical_themes": [
    {{
      "theme_id": "AT-{silo_code}-001",
      "theme_label": "<analytical theme name, interpretive>",
      "interpretation": "<2-4 sentence analytical interpretation>",
      "grounded_in": ["DT-{silo_code}-001", "DT-{silo_code}-003"],
      "counter_evidence": "<what does NOT fit this theme? Which papers contradict it?>",
      "implication": "<what does this mean for the field's trajectory?>"
    }}
  ]
}}
```

RULES:
1. Every analytical theme MUST be grounded in at least one descriptive theme.
2. Every analytical theme MUST have a counter_evidence field — what doesn't fit?
3. Do not simply rename descriptive themes as analytical. Analytical themes must ADD interpretation.
4. Candidate themes only — the researcher will accept/reject/restructure before they are finalised.

Output ONLY the JSON object. No markdown wrapping.
