### Concerns raised by Vincent

- Implementation is structurally a generic variational ansatz, not the paper's QSVT+LCU+block-encoding MEDL/WDM construction.
- Compute-uncompute (ansatz . ansatz^dagger) collapses to (approximately) the identity on |0>, so the 'full' variant does not exercise any oracle-like sub-block; it is not a meaningful proxy for the paper's exponentiation-via-QSVT step.
- Paper does not state a data-qubit count, so the scale_faithful check cannot be verified against a concrete paper number; the n=5 choice is set by the proxy template, not by the paper.

### Recommendations from Vincent

- Document this entry as a known ansatz_stretch template proxy in the Phase-8 cost model (do not interpret its resource cost as estimating SI-PQC/MEDL/WDM cost).
- If a more faithful proxy is desired later, replace the full-variant compute-uncompute with a small block-encoding-style toy oracle (e.g., a controlled rotation chain emulating one constraint f_k) so the oracle accounting reflects QSVT/LCU structure rather than identity.
- Consider lowering claimed coverage for SQ21/SQ22/SQ23 (same paper) in any downstream 'algorithm-family faithfulness' tally.
