- instance.notes itself states 'does NOT implement the paper's algorithm' -- proxy faithfulness is acknowledged-absent.

### Recommendations from Vincent

- If kept as a stretch proxy, rename labels SQ6 -> SQ25 across instance.json, @register, and register_accounting to remove cohort/identifier drift.
- Reconcile n_qubits: either set instance n_qubits=2 to match v2 canonical, or document the choice (max-photon 4-qubit demo) in instance.notes and v2 citations.
- Consider implementing a minimal LMR-faithful proxy: 1 ancilla + 1-3 data qubits, amplitude-encode two reference vectors, Hadamard-controlled state preparation, ancilla projection in X basis, derive inner product from p. Even at small scale this would make the family check honest.
- Add a 'proxy_faithfulness=template_only' flag in instance.notes so downstream resource-estimate aggregation does not over-claim algorithmic fidelity for SQ25.

This routine is then used for supervised nearest-neighbor classification and unsupervised clustering.

It does not contain the defining structures of the paper's algorithm: no amplitude encoding of the input and reference vectors |u> and |v>, no explicit ancilla-controlled entangled state preparation, no X-basis or projective ancilla measurement corresponding to the paper's distance estimator, and no distance/inner-product extraction path.

    The mismatch is major because the paper's algorithmic primitive is precisely the entanglement-based measurement routine. Replacing it with a generic RealAmplitudes identity-like compute-uncompute circuit loses the central resource and structural content of the paper.

    The paper is photonic and experimentally implemented with polarization/spatial-mode encodings, so any Qiskit gate-model version is necessarily a proxy. However, a small gate-model proxy can still preserve the algorithmic skeleton much better than the current ansatz: one ancilla, data-register state preparation for |u> and |v>, controlled preparation / multiplexing, and ancilla-basis measurement.
