## Verdict summary

Generic RealAmplitudes ansatz-stretch proxy at 5 qubits; paper does not state a single qubit count for exp_3 (range 3-15) and the algorithm is QAS-discovered PQC -> CPQC -> Amplitude Estimation, so the proxy is a defensible template but lacks AE/oracle structure.

## Checks

### ✅ Family-faithful

Cohort family is 'other-gate-based'; paper exp_3 is a hybrid QAS-discovered PQC + AE pipeline. A variational ansatz template is a reasonable bucket-level proxy under the template-proxy methodology.

### ✅ Scale-faithful

Paper reports a 3-15 discretization-qubit range with no single canonical value; n=5 sits inside that range and within the 12-qubit tractability cap.

- `v2_n_qubits`: `None`
- `circuit_n_qubits`: `5`

### ✅ Structurally non-trivial

RealAmplitudes(reps=3, linear) plus compute-uncompute pair gives a non-trivial parametrized ansatz with two-qubit entanglement, consistent with a PQC payoff-circuit proxy; however no QFT, no Grover/AE oracle, no Hadamard test.

### ❌ Metadata-consistent

instance.json algorithm_variant_paper field says 'QFT-based European call pricing, version 1 discretization with Hadamard test', but the v2 extraction's exp_3 is QAS-discovered PQC -> CPQC -> Amplitude Estimation (QMCI). The variant label appears to describe a different experiment from the same dissertation.

## Concerns

- instance.json algorithm_variant_paper describes a QFT/Hadamard-test pricing variant, while the v2 extraction characterises exp_3 as a QAS-PQC + AE pipeline; label and extraction disagree on which sub-experiment is being proxied.
- Circuit implements neither a QFT nor an Amplitude Estimation oracle, so it does not exercise either of the paper's two main algorithmic threads beyond a generic ansatz.
- v2 operator_notes flags SD14/SD15/SD16 as the same paper with possible cohort redundancy; verdict here only judges SD14 but the redundancy is worth tracking.
- Paper does not state a single qubit count for exp_3, so the scale check is necessarily loose.

## Recommendations

- Either reconcile instance.json's algorithm_variant_paper with the v2 extraction (set it to a QAS-PQC + AE description) or, if the QFT variant is the intended proxy target, switch the template family accordingly.
- If a tighter proxy is desired later, consider an ansatz wrapped in an Iterative Amplitude Estimation skeleton (Q-operator + inverse) to better reflect the AE oracle structure called out in the paper.
- Audit SD14/SD15/SD16 jointly to confirm they correspond to distinct exp_ ids on this dissertation rather than duplicates.
