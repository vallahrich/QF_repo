## Verdict summary

Defensible template proxy: family tag 'other-gate-based' matches both paper and circuit, scale is small/tractable, but the implementation is a generic RealAmplitudes ansatz with compute-uncompute and does not reproduce the AE/AA-based Quantum Sparsitron structure described in the paper.

## Checks

### ✅ Family-faithful

Cohort and circuit both tag algorithm_family='other-gate-based'. Paper's Quantum Sparsitron is a hybrid AE/AA/quantum-min-finding routine that does not fall in any of the canonical buckets (HHL/QAE/QAOA/VQE), so the 'other-gate-based' bucket is appropriate for both paper and proxy.

### ✅ Scale-faithful

Paper does not state a concrete num_qubits for exp_3 (NOT_STATED in v2 extraction); implementation uses n_qubits=5, which is well under the 12-qubit tractability cap and acceptable as a small-scale stretch.

- `v2_n_qubits`: `None`
- `circuit_n_qubits`: `5`

### ❌ Structurally non-trivial

Circuit is a generic RealAmplitudes(linear) ansatz plus its inverse for the 'full' variant — i.e., a parameterised variational template followed by compute-uncompute. There is no quantum inner-product estimation, no amplitude estimation/amplification subroutine, no QFT, and no minimum-finding structure that would reflect the Quantum Sparsitron's AE/AA-based design. The instance.json and registration both explicitly disclose this is a template proxy ('paper algorithm not implemented').

### ❌ Metadata-consistent

circuit.py registers under label='SQ15' (and uses 'SQ15_bare'/'SQ15_full' names) while this audit row is label_id='SQ16'. instance.json also carries instance_id='SQ15_v5_proxy_v1' and label='SQ15'. The instance notes explain the situation (SQ16/exp_3 is a v5 extra experiment row of the same paper_id whose covered v2/v3/v4 label is SQ15), so this is a documented label-aliasing artifact rather than a wrong-paper bug, but it is a real metadata inconsistency for the SQ16 row.

## Concerns

- Implementation is a generic variational ansatz proxy; it does not implement the paper's Quantum Sparsitron (AE + AA + quantum inner-product estimation + quantum minimum finding).
- Encoding in v2 extraction is 'amplitude' (amplitude-encoded weight states); proxy uses parameterised gate-model state prep, which does not reflect amplitude encoding from a QRAM oracle.
- Oracle structure in v2 is 'amplitude_estimation'; proxy oracle is an ansatz . ansatz^dagger compute-uncompute pair, which is structurally unrelated to amplitude estimation.
- Label/identifier drift between cohort row (SQ16) and circuit/instance metadata (SQ15) — explained in instance notes as a v5 extra-experiment artifact, but still inconsistent at the file level.

## Recommendations

- If feasible within the template-proxy methodology, swap to a Phase-8 stretch template that at least includes an amplitude-estimation-shaped subroutine (state-prep + Grover-style oracle + inverse QFT) so the structural fingerprint is closer to the paper's Quantum Sparsitron.
- Add an alias / cross-reference field (e.g., 'cohort_label_id': 'SQ16') in instance.json and a comment in circuit.py noting that this SQ15-named circuit is reused for the SQ16/exp_3 cohort row of paper 7eefd96d7f06.
- Document in canonical_build_log.md (or equivalent) that the 'other-gate-based' bucket here covers a hybrid AE/AA/min-finding algorithm, so downstream resource-estimate aggregation does not silently treat this as a pure variational workload.
