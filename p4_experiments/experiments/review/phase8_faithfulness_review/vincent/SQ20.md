## Verdict summary

Family-faithful quantum-svm proxy with paired-inverse kernel structure at near-paper scale (3 vs 2 qubits), but uses amplitude-encoding template rather than the paper's ZZFeatureMap encoding and the instance/circuit are mislabeled SQ13.

## Checks

### ✅ Family-faithful

Both v2 extraction and circuit register algorithm_family='quantum-svm'; the encoder/encoder^dagger paired-inverse structure matches the QKE kernel-estimation pattern U_Phi(x_i)^dagger U_Phi(x_j) used in the paper.

### ✅ Scale-faithful

Paper reports n_qubits=2 for the SX5E exp_2 task; instance sets n_qubits=3. Within factor-of-2 tolerance and below the 12-qubit cap.

- `v2_n_qubits`: `2`
- `circuit_n_qubits`: `3`

### ✅ Structurally non-trivial

Bare circuit applies a parameterized encoder ansatz with measurement; full accounting variant uses encoding_paired_inverse, which mirrors the paper's transition-amplitude kernel circuit shape. Non-trivial multi-layer (encoder_layers=4) ansatz.

### ❌ Metadata-consistent

instance.json sets instance_id='SQ13_v5_proxy_v1' and label='SQ13'; circuit.py registers label='SQ13' and circuit name 'SQ13_bare'/'SQ13_full' even though the cohort entry is SQ20. Encoding tag in v2 is 'angle' (ZZFeatureMap = angle/Pauli evolution) while template is amplitude-encoding.

## Concerns

- Label mismatch: instance.json and circuit.py registration use 'SQ13' rather than 'SQ20'. Potential cohort/registry collision and confusion in result aggregation.
- Encoding mismatch: paper uses ZZFeatureMap (second-order Pauli-Z evolution, full entanglement, reps=2); proxy uses generic amplitude-encoding template. Acceptable as a template proxy per methodology, but encoding family differs from the paper's reported angle/Pauli-Z map.
- Qubit count off-by-one (3 vs 2) for this specific SX5E experiment row; the cohort note explicitly says the v3/v4 covered row was a different experiment (TSX, n_qubits=3), so the n_qubits=3 here likely leaks from the sister experiment.
- Shots in v2 carry a documented conflict (1024 vs 210); instance uses 1024 which matches Methodology but not Findings. Not a circuit-faithfulness issue, but worth flagging.

## Recommendations

- Rename instance label/id and circuit registration label/name from 'SQ13' to 'SQ20' to fix the metadata collision.
- Set parameters.n_qubits=2 to match the SX5E exp_2 row's reported feature_dim/n_qubits.
- If feasible without changing cohort scope, swap amplitude_encoding template for a ZZFeatureMap-paired-inverse template to better mirror the paper's QKE kernel circuit; otherwise document the encoding-family substitution explicitly in operator_notes.
