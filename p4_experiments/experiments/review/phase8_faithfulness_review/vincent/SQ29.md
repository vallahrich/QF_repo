## Checks

### ✅ Family-faithful

Paper is QCBM (variational quantum generative model, quantum-ml family); circuit uses a parametrised RealAmplitudes variational ansatz, same algorithm_family bucket (quantum-ml / variational-NISQ).

### ✅ Scale-faithful

Circuit uses 6 qubits, exactly matching the paper's primary configuration (6-qubit qopula, 3 qubits per variable).

- `v2_n_qubits`: `6`
- `circuit_n_qubits`: `6`

### ✅ Structurally non-trivial

Bare circuit is a multi-layer RealAmplitudes ansatz (ansatz_layers=3); full variant adds an ansatz/inverse compute-uncompute pair plus measurement. Non-trivial parameterised entangling structure consistent with a variational-NISQ proxy, though not the paper's exact RZ/RX/RZZ qopula gate set or 8-layer depth.

### ✅ Metadata-consistent

Registry algorithm_family='quantum-ml' matches v2 extraction (model_class=QCBM, framework=PennyLane, ansatz_type=custom). Instance n_qubits=6 matches v2 num_qubits=6; ansatz_layers=3 in instance differs from v2 ansatz_layers=8 (proxy reduces depth) but matches authoring_n_used and is documented in instance notes as a template proxy.

## Concerns

- Proxy uses RealAmplitudes with linear entanglement rather than the paper's qopula ansatz (RZ, RX, RZZ gates acting per-variable); structural detail is simplified.
- Instance ansatz_layers=3 vs paper's primary 8-layer configuration (v2 ansatz_layers=8); depth scaled down for tractability, may underestimate two-qubit gate cost in resource extrapolation.
- Circuit does not implement QCBM training (SPSA / annealing / genetic algorithm) — this is by design under the template-proxy methodology and explicitly noted in instance.notes.

## Recommendations

- If resource estimates depend sensitively on depth, consider also running an 8-layer variant to bracket the paper's claimed depth.
- Document in cohort metadata that the qopula-specific gate structure (RZZ entanglers) is replaced by the RealAmplitudes CX-ladder, so entangling-gate counts are a lower bound for the paper's true ansatz.
